# konnte nicht sagen, welche Versionen im laufenden Container stecken. Jeder
# Eintrag hat jetzt zusaetzlich eine Obergrenze beim naechsten Hauptsprung,
# damit ein Major-Upgrade (das erfahrungsgemaess Verhalten aendert) bewusst
# hier eingetragen werden muss und nicht beim naechsten Image-Build passiert.
#
# Konkreter Anlass: aiosmtplib ist von 3.x auf 5.x gewandert, ohne dass sich
# im Repo etwas geaendert hat; in 5.x verbietet send() sock= zusammen mit
# port=. Mit Obergrenze waere das beim Aktualisieren aufgefallen statt im
# Betrieb.
#
# Noch offen: echtes Lockfile mit Hashes (pip-compile/uv lock auf Python 3.13,
# passend zum Laufzeit-Image). Die Abhaengigkeiten werden zusaetzlich im CI
# mit pip-audit gegen bekannte Schwachstellen geprueft (.github/workflows/ci.yml).
